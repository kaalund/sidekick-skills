# Design Start

Set up the design memory for a Figma file and write a first project brief from the form answers and what the file shows. Work silently and keep your messages short and casual.

1. Load `resolve` and resolve the file and folder. Load `memory-format` and `figma-use`. If there is no seed and the file is not in the registry yet, stop and tell the designer to press Get started on the Sidekick card: the form writes the seed with the real file name, and `resolve` would otherwise guess a name from the URL (`figma.root.name` is "Document"). Write nothing.

2. **Detect existing memory** with `use_figma` (read-only; nothing is created until the step 3 preflight passes): `findMemorySpec`, then the legacy page `🤖 Agentic Memory` (or `Memory (agent-maintained)`).
   - Spec exists: say it is already set up and create nothing, but the preflight at the start of step 3 still runs (including the library check), and so do steps 4 to 6. On a re-run, never overwrite a brief value the designer edited or commented on (`memory-format`, Inferred content): only fill keys that are missing or still `unknown` or `(inferred)`. Never overwrite a brief line that carries a designer comment, even when it still ends in `(inferred)`: `parseMemory` strips comment markers through `plain()`, so check the raw lines from `readMemoryMarkdown` for `[comment:` before overwriting a line. Never add a second `Q-` line for a key that already has one, open or closed (also under `### Answered`): match on the key's question text (for example `Which platform ...`) against the existing `Q-` lines. A Retry after a blocker (`needs=...`) and a restarted onboarding both land here. A review that found no memory spec (`needs=memory`) sends the designer here too, via Retry on the card; with no seed the brief is inferred as in step 6, since the seed is optional. No spec yet: step 3 creates it.
   - Only the legacy page exists: after the step 3 preflight has passed, migrate it into a new spec (`memory-format`, Legacy memory page), then carry on as above.
   - Never create a second spec.

3. **Preflight, then create what is missing.** First run the Preflight (`memory-format`, Preflight) with checks `specs`, `login` and `library` (a fresh `get_libraries`: on a Retry the designer enabled the library after the first stop, so a result from earlier in the conversation is stale). Skip `memory` (this step creates the spec) and `empty-target`. This is the first thing that can stop `start`, so create nothing before it passes. The library check does not need the spec, which is why it runs before `createMemorySpec`. If any check fails, print every blocker with its fix, write the state file with `stage=start`, `needs=<first failing check>`, `detail=<its fix>` and an empty `progress` (the stage line is ignored without a stage), and stop: never `detail=brief interview` while a blocker stands. Retry on the card runs this skill again.

   Then create the spec with `createMemorySpec`, seeded with the five sections in the order of `memory-format` (`## Open questions` first, left empty). The anchor is the node in the start link (or the seed's `url`), else the current selection, else the page; switch to its page first. Seed these entries under `## What I know` if absent:
   - `### Flows`: a single bullet `(no flows registered yet)`.
   - `### Not covered yet`: a single bullet `- I have not looked at any frame yet.` Step 5 replaces it.

   Last, resolve the `Finding` key from the library check above (`memory-format`, Findings, Finding library). Do not build the component set.

4. **Read before writing.** List the file's pages and the first-level nodes of the first page with one `use_figma` script (`id|type|name|WxH`, never `get_metadata` on a page: it returns the whole tree), and call `get_libraries` for linked libraries. If the seed from the Sidekick card exists (`~/Library/Application Support/Sidekick/seeds/<slug>.md`, the one `resolve` found), read it with the Read tool, never with shell `cat` or other shell reads (the auto-mode safety check blocks those outside the folder): every section that is not `unknown` is an answer you already have. Then update the stage line (`memory-format`): `stage=start`, `detail=brief interview`. Do this here: the spec, the library and the entries are in place, and this write marks onboarding as in progress for the Sidekick card. The value is only a marker, no interview follows. Omit `needs` in this write: a successful write never carries a stale blocker over. Never write it before step 3 has finished, and never when step 3 stopped on a blocker (`needs=...`).

5. **Look at the first screens.** Take at most the first 3 top-level frames in the file (from the first-level list) and read the visible copy of each with `use_figma` (its text nodes). `get_design_context` is not needed here and needs `figma-design-to-code` loaded first. Together with the names of the pages, sections and frames, that is all you have to go on. Never ask the designer anything: this skill is silent. Then say what you did and did not see in `### Not covered yet` (`memory-format`, What I know), in plain words, for example "So far I have only looked at the first 3 frames (<names>). The other <n> frames are not described yet, and no flows are registered until you press Review on a frame or section." Only replace the seeded placeholder or a line `start` wrote earlier (`replaceLines`); once a review has written its own gaps there, leave them.

6. **Write the brief.** Write the `### file` entry under `## Brief` straight to the spec, with no approval step and no questions; the designer reads it there next to the flows and corrects it with a comment (`setKey` for each key of an existing entry, `addEntry` for a new one). On a re-run, apply the re-run rules of step 2 to every key. Per key:
   - The seed's sections map to the brief keys: Purpose and problem to `purpose`, Users and audience to `users`, Goals and success to `goals`, Platform to `platform`, Brand to `brand`. A seed answer that is not `unknown` is written verbatim, with no marker.
   - `constraints` is always `WCAG compliance is mandatory`, plus any limit the seed's Scope of this file section names; with no limit, the seed's scope goes into `purpose`.
   - Every other key (`purpose`, `users`, `goals`, `platform`, `brand`, `references`, `risks`) that the seed did not answer is inferred from what steps 4 and 5 showed, with `(inferred)` appended (`memory-format`, Inferred content). Only when there is nothing to go on, write `unknown` and add a `Q-###` line for it under `## Open questions` (`nextMemoryId(md, "Q")`, scope `file`, one line per unknown key, skipped when a `Q-` line for that key already exists, open or closed, for example `Which platform is this for?`).
   - Do not copy the brief to disk: Figma is the only copy, so teammates see it. Do not delete the seed either, Sidekick removes it once the stage line says `brief written`.

7. **Folder.** `resolve` already registered the file. In the shared design folder there is nothing more to set up: the folder, its git repo and its `.claude/settings.json` already exist (the Sidekick card sets them up).

8. End with two lines: what was created (and that the brief and what I know are in the memory spec next to the flows to read, open questions on top), and the suggested next step: select a single frame or journey section in Figma, then press Review on the card. Update the stage line (`memory-format`): `stage=start`, `detail=brief written`.
