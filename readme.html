design-memory

A Claude Code plugin that gives a Figma file a memory. It writes down the brief, what changed and why, and open questions in one Figma spec. It runs critiques and puts the findings on the canvas, under the frames they are about. Seven skills: two you run, four internal helpers, and one emergency fallback.

You (or the card) start these Internal helpers, loaded by other skills Other plugins, picked from the catalog Emergency fallback

How they connect

The Sidekick card starts start or review. They pull in helpers; every skill reads the same contract.

What each skill does

They work silently and never ask you to confirm a guess. The only questions: what a new flow is for (context), and a confirm before the fallback builds anything.

start

/design-memory:start

Sets up memory for a Figma file. Creates the 🤖 Agentic memory.md spec next to the designs (or migrates the old Memory page) and writes a first file-level brief.

Reads
Sidekick form seed, first 3 frames, page and section names
Writes
The spec, the .state file, the registry entry
Note
Guesses end in (inferred). Your edits and comments always win on a re-run.

review

/design-memory:review [alias]

One silent pass. Catches the memory up with what you did in Figma, picks the critique that fits the flow's stage, runs it, and puts the findings on the canvas.

Reads
Findings you triaged, the digest, the memory in scope
Writes
Change log, Finding instances, questions, status, .state
Note
Early-stage minor findings are parked until polish.

context

internal

Works out which flow the selected frame belongs to and loads only the memory that applies. Registers a new flow on first use and asks once what it is for.

Reads
Spec index, node ancestors, decisions, findings
Returns
Flow chain, kept entries, the "already considered" list

digest

internal

Looks at the frames before anyone critiques them. Compares fingerprints with the cache, classifies each as edit, variant, state or new, and infers the flow's stage (explore, refine, polish).

Reads
Frames in scope, local cache
Writes
Local cache only, never Figma
Returns
Change list, stage, package for the critic

resolve

internal

Finds the Figma file key, the shared design folder and the file's slug, and registers the file in the config on first use.

Reads
Figma URL, environment.json, config, seed
Writes
.design-memory/config.json

memory-format

internal, the contract

The one source of truth. Spec layout, entry formats, ID rules, the Finding component, preflight checks, state file keys, cache layout, and the Figma helper code. If a skill disagrees with it, it wins.

build-finding-component

/design-memory:build-finding-component

Builds a local copy of the Finding component when the Sidekick library can't be enabled. Checks that it really can't, then asks you to confirm before building.

Note
A local copy won't follow later library changes.

One review, step by step

What happens when you press Review on the card.

  1. PreflightChecks everything in one pass. Any blocker stops it before Figma is touched.review + memory-format
  2. ScopeFinds the flow, loads its memory. Asks about a new flow.resolve, context
  3. DigestDescribes what changed since last time. Infers the stage.digest
  4. Catch upLogs your triage and edits to the change log. Marks fixed findings Done.review
  5. CritiquePicks a check by stage and what hasn't run, then runs it.catalog skill
  6. WriteDrops findings under their frames. Parks minor ones early on.review
  7. Hand overUpdates status and the state file. The card shows the result.review

What a finding goes through

You triage in Figma by changing the Status property. The next review reads it back.

Open → Will do On hold (also gets a Q- question) Dismissed Done

Open, Will do and On hold stay on the canvas. Dismissed and Done are removed by the next review, which keeps a one-line digest on the change log so the same thing isn't raised again.
